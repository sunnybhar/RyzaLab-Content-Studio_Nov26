# Automatic first writing

The founder can enable automatic first writing in AI & budgets → Review and preparation. It is offered during new policy setup; existing policies retain their saved choice until explicitly changed.

When a person selects a new idea with that policy enabled, Studio creates one linked draft and records their actor, policy, original revision and exact source/workflow context. The signed-in API prepares a canonical writing request, with maintenance recovery if setup or the first response was interrupted. Reopening an existing linked draft does not create another intent or request. Older drafts are never scanned for automatic writing merely because the setting is enabled.

The selector still needs read, create/edit and job permissions plus a current actor-scoped package allowance, validated writing connection and qualified prices. All existing monetary limits apply. Missing setup or exhausted budget saves the draft and shows an actionable message. The founder can authorize a creator's package separately; selecting an idea does not confer approval authority.

Only one new writing request is prepared per maintenance pass. Human edits, changed source/workflow context or a new policy stop the original automatic request. Dispatched results are pinned to their target and cannot overwrite a changed or approved draft. The editor locks local inputs while automatic application can occur, and preserves unsaved edits if another session updates the saved version.

Failed, cancelled, incomplete or uncertain first attempts remain retained and are never automatically retried. Existing writing requests, including explicit manual requests, prevent an automatic duplicate. Inspect the saved candidate or use Write with AI explicitly after resolving a known outcome; unknown work must be reconciled first. Complete structured results can attach directly; unanswered facts and incomplete results remain candidates rather than fabricated finished content.

Automatic writing produces the selected piece's copy, not a published post or a completed image/video/audio asset. Human copy and final-package decisions remain separate. Demo does not run paid providers; browser tests simulate provider completion only in isolated local fixtures.

Verification:168 domain tests, production build, full browser regression, updated founder-policy harness and isolated idea→one draft→queued lock→direct completed-copy test passed. No live providers, environment changes, policy adoption or database writes were performed during this development.
