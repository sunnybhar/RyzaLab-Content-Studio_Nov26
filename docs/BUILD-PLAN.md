# Studio rebuild — approved product baseline

Development routing: GPT-6.1 Sol for normal implementation/fixes and screenshot-driven visual refinements. GPT-6 Astra performs focused data/workflow review before implementation, permissions/approval/manual-publication review before implementation and release. Runtime providers are separately configured by function. Record actual reviews; do not claim that a configured development model changes API generation models.

Operational content lives in Studio; no Notion. Google Docs live editing + DOCX import/export; manual fetch default. Manual human publication only. Nine content workspaces; founder/admin/permitted-writer unified versioned workflow setup. Profiles assigned by email; initial admin only, explicit founder assignment. Human final decision; protected factual integrity rules cannot be waived. Partial edits retain existing media. Immutable approved snapshots; schedule-package replacement explicit. New York timezone; unmatched tasks route to founder; 90-day Trash with dependency protection and retained release snapshots. Inbox + email configuration. Models and encrypted credentials per function. No paid test allowance or hosting selection approved.

Persistence design to review: server-authoritative command reducer with versioned workspace state, row-locked compare-and-swap PostgreSQL RPC, separate append-only release packages/audit table and separate encrypted provider credentials. Browser cannot directly read/write canonical state/keys; authenticated server validates membership and all scope dimensions in one grant, applies typed commands, persists with expected workspace version. Responses filter content, jobs, packages, references, workflows, notices and scopes. Backward endpoints cannot bypass new command/budget gates. Service-role DB access is restricted to server/worker adapters. A future normalized schema must preserve the command contract. Sources and media files stored privately with selected-version references.

Durable job protocol: queued -> running -> succeeded / failed / unknown; no blind retry of unknown. Spending reserved before queue, confirmation threshold never bypasses caps. Worker callbacks require server secret and lease/version check. Without provider credentials or authorized budgets, jobs cannot execute. External Docs OAuth, email delivery and video provider evaluation remain credential/hosting gates, not mock successes.

Migration must preserve legacy draft/campaign/member rows, import legacy drafts and apply canonical access restrictions. Supabase migrations not applied remotely in this task. Preview/demo and credentialed integration validation distinguished.
