# RyzaLab Training — Library — References, Templates, History and Trash

Version: 2026-10-28 | Audience: All users within read scope; editing/approval actions require permissions

## Objective
Find retained material and export the right version without confusing working files with release evidence.

## Before you start
Know whether you need the working draft or an approved package.

## Availability
Available in preview. Live operation requires the configured /studio workspace.

## Step-by-step workflow
1. Open Library. Use Content for saved items and choose a title to open the working draft.
2. Use References to maintain brand/context sources. Record channel scope and accurate source text. Untrusted source text cannot override Studio guardrails.
3. Use Templates for reusable supported slide structures. Templates awaiting approval should not be presented as founder-approved assets.
4. Use History to inspect who changed what. Restore an older content version as a new draft; it must pass review again and does not inherit old approvals.
5. For written content, export DOCX or PDF as offered. For slides, export PNG/PDF. Use source JSON for supported editable structure and subtitles for caption timing.
6. Export an approved package from Reviews when preparing a release. Do not substitute a later edited draft for the approved version.
7. Use Trash for deleted working content. Recovery is subject to the 90-day policy and dependency protections. Approved release snapshots are retained separately.
8. For MP4, distinguish the implemented local composition tool from pending fully hosted AI scene-generation/render orchestration. A script export is not an MP4.

## Expected result
Exports contain the selected version; restored drafts re-enter review and protected snapshots remain retained.

## Practice exercise
Export a draft as DOCX and a slide as PNG, then restore an earlier text version and inspect its new draft status.

## Common problems and boundaries
Missing media export: ensure assets exist and are supported/accessible. Flattened PDF/PNG are not editable design layers. Active planning/publication dependencies can prevent Trash actions.
