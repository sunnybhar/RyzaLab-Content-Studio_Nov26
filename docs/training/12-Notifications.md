# RyzaLab Training — Notifications — Inbox and Reminders

Version: 2026-10-30 | Audience: Each member for their own inbox

## Objective
Read workflow reminders and understand delivery prerequisites.

## Before you start
Have an event that creates a notice. Due reminders require maintenance to run.

## Availability
Available in preview. Live operation requires the configured /studio workspace. Release 0.3.2: the two-decision flow requires explicit founder adoption; any legacy stage instructions below apply only before adoption. No paid provider or live-account acceptance is implied by these documents.

## Step-by-step workflow
1. Click the bell or Notifications to open your inbox.
2. Read the event and affected content/task. Open the corresponding section to take the required action.
3. Use available read/dismiss controls to clear the unread state after reviewing the message.
4. For due planning work, open Calendar and use Open draft / Open workflow. Complete or move the task as appropriate.
5. For publication reminders, inspect the exact package and handoff before posting. A reminder never publishes automatically.
6. Test email only after the transactional email service and dispatch schedule are configured. Password login is independent of notification email.
7. If no reminder appears, check the task time, timezone, maintenance schedule and your membership before assuming an event failed.

## Expected result
Inbox notices identify events honestly and never substitute for approval or publication.

## Practice exercise
Read the sample welcome notice, then test a due task reminder in an authorized maintenance test.

## Common problems and boundaries
Preview actions do not send email. Repeated maintenance should not duplicate the same due reminder. A stale reminder can remain in history after the underlying task changes.
