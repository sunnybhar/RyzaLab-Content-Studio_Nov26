# RyzaLab Training — Reviews — Nine Stages and Human Approval

Version: 2026-10-30 | Audience: Reviewer/manager with grants, founder or authorized approver

## Objective
Release the exact reviewed package while preserving evidence and human authority.

## Before you start
Have a saved draft and active workflow. Only authorized profiles can approve packages.

## Availability
Available in preview. Live operation requires the configured /studio workspace. Release 0.3.0: the two-decision flow requires explicit founder adoption; any legacy stage instructions below apply only before adoption. No paid provider or live-account acceptance is implied by these documents.

## Step-by-step workflow
1. Reviews uses compact full-width summaries. Open review displays the selected package in a popup.
2. Before founder adoption, the legacy recorded-stage workflow still applies. After adoption there are two explicit human decisions: copy, then final package.
3. Read the exact copy, captions, narration and slide wording and check factual claims against supplied references. Record what you actually checked before Approve copy.
4. Automatic textual review is prepared only if enabled and within the actual package allowance. Missing setup, exhausted funds or uncertain work remain blockers. Same-provider second pass is not independent.
5. Resolve blocking findings and missing facts. Incomplete or stale responses are not a successful current report; retained output never authorizes a blind paid retry.
6. Inspect actual text and assets plus the exact platform/account. Explicitly approve the final package; Notes also need founder release authority and required independent review.
7. An authorized calendar manager receives an immediate date/time planner for that immutable package. Canceling the planner retains the approval and ready-to-plan item.
8. Publishing remains a person’s external action. Changed released wording requires current copy/final approval again.

## Expected result
Only a human can approve; approval, handoff and publication refer to the exact package and retain their history.

## Practice exercise
Try approving before the six checks: it must fail. Complete the checks, approve, edit text and verify the old package is retained.

## Common problems and boundaries
Stale workflow/rule/revision: reread current content and repeat affected checks. Founder pricing exceptions are exact-wording/revision scoped; they do not override factual blockers.
