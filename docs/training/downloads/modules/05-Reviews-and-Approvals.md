# RyzaLab Training — Reviews — Nine Stages and Human Approval

Version: 2026-10-28 | Audience: Reviewer/manager with grants, founder or authorized approver

## Objective
Release the exact reviewed package while preserving evidence and human authority.

## Before you start
Have a saved draft and active workflow. Only authorized profiles can approve packages.

## Availability
Available in preview. Live operation requires the configured /studio workspace.

## Step-by-step workflow
1. Open the draft stage tracker. Intake confirms topic, audience, channel and selected source.
2. Record Evidence after checking factual claims, provenance and permissions. If there are no external factual claims, explain that explicitly; do not skip the stage.
3. Record Creation once the required text and media are present. Record Independent review with the actual reviewer and findings. Founder self-review is allowed but must be described truthfully.
4. Record Visual review after inspecting required images, slides, crops, captions or scenes. N/A is only for a genuinely text-only format and needs a meaningful reason.
5. Record Release check against the exact current text, media, active workflow and protected rules. A hold or revise decision reopens later checks.
6. In Reviews, compare the submitted revision and choose Approve revision, request changes or reject as appropriate. All six prior checks must be current before approval.
7. Approval creates an immutable package snapshot. It does not publish anything, and it cannot waive misinformation or misrepresentation controls.
8. Open the approved content and record Publication handoff for the exact package to be exported or copied. A different approved package needs its own handoff.
9. After a person actually publishes, record Publication record through Calendar → Confirm published and provide the correct URL.

## Expected result
Only a human can approve; approval, handoff and publication refer to the exact package and retain their history.

## Practice exercise
Try approving before the six checks: it must fail. Complete the checks, approve, edit text and verify the old package is retained.

## Common problems and boundaries
Stale workflow/rule/revision: reread current content and repeat affected checks. Founder pricing exceptions are exact-wording/revision scoped; they do not override factual blockers.
