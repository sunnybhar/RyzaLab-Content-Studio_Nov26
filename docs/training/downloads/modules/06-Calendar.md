# RyzaLab Training — Calendar — Drafting, Editing, Workflows and Publication

Version: 2026-10-30 | Audience: Users permitted to edit the target; authorized publication planners

## Objective
Plan work and manual publication, open the correct target, and record completion.

## Before you start
A draft or workflow must already exist for work tasks. Publication requires an approved package.

## Availability
Available in preview. Live operation requires the configured /studio workspace. Release 0.3.0: the two-decision flow requires explicit founder adoption; any legacy stage instructions below apply only before adoption. No paid provider or live-account acceptance is implied by these documents.

## Step-by-step workflow
1. After two-step final approval, a permitted calendar manager receives a date/time planner for the exact returned approved package. Time stays blank until chosen. The ready tray and read-only approved snapshot preview remain available if planning is postponed.
2. Open Calendar. Choose Month or Agenda. Read the displayed Studio timezone; times are entered in that timezone.
3. Click Add to calendar, choose Drafting, Editing, Workflow work or Approved publication, then Continue. Alternatively use Plan drafting, Plan editing, Plan workflow or Plan publication.
4. For a work task, enter Task title, select the existing Draft or Workflow, choose a future Task time, add notes and Save planning task. A task never starts an agent or approves content.
5. Click a date number to begin planning work for that day. If the selected default time is already past, change it to a future time before saving.
6. Click a work event to open its linked draft or workflow. The task list below the calendar also provides Open draft / Open workflow, Move task, Mark done and Cancel task.
7. For publication, choose the exact approved package, its publication time and optional campaign group. Save it to the calendar. An unapproved draft is not eligible for publication scheduling.
8. Click a publication event to open its draft. Use Agenda for publication management: Move, Replace approved package, Block or Confirm published.
9. Before publishing, verify the correct package has a passed Publication handoff. A human publishes outside Studio.
10. Only after the post is live, use Confirm published with its HTTPS destination URL. Match the selected approved revision. Studio records the human confirmation; it does not auto-post.
11. Due planning reminders are created when maintenance runs. Test live reminder delivery only after the worker/maintenance schedule is configured.

## Expected result
Work tasks and publications are visibly distinct; tasks open the correct target and never imply permission to publish.

## Practice exercise
Schedule one editing task for tomorrow, open its draft, move it, mark done, then schedule a workflow review. Test publication separately with an approved sample.

## Common problems and boundaries
Cannot trash a draft with active tasks: complete/cancel those tasks first. Missing approved packages: complete Reviews first. A blocked publication must be explicitly rescheduled before confirmation.
