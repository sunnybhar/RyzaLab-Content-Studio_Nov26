# RyzaLab Training — Workflow Settings — Instructions, Brand Sources and Guardrails

Version: 2026-10-30 | Audience: Writer/editor with workflow permission; authorized activator; founder for protected policy

## Objective
Maintain channel-specific agent behavior in one reviewed workflow.

## Before you start
Select the target channel and gather approved brand/reference material.

## Availability
Available in preview. Live operation requires the configured /studio workspace. Release 0.3.0: the two-decision flow requires explicit founder adoption; any legacy stage instructions below apply only before adoption. No paid provider or live-account acceptance is implied by these documents.

## Step-by-step workflow
1. Choose a highlighted channel tab across the top. Keep workflows collapsed until needed; instruction reading opens separately. Setup is reused for later drafts and does not require reactivation for every post.
2. Open Workflow settings and choose the channel, including Notes/Newsletter where relevant.
3. The channel has one current workflow card. Check Created/Updated timestamps, active or pending state, and Text/Ideas bindings. Expand it to read instructions in a popup; earlier revisions are inside collapsed Revision history.
4. Import a channel preset if needed. The import creates a draft, not an active replacement. Live imports use the uploaded channel material; preview imports sanitized samples.
5. Create or save a draft version. Add channel instructions, audience constraints, output requirements and applicable brand/reference records. Treat uploaded documents as reference material, not permission to change protected policy.
6. Use Edit workflow for instructions and Edit connections for model mappings. Choose No connection (remove binding) to clear a mapping. Save changes updates an existing draft in place with an Updated timestamp. Editing active/reviewed instructions creates a pending internal revision in the same card; submit and activate after review. Historical snapshots and credentials remain preserved.
7. Submit the draft for review. An authorized activator chooses Approve & activate after checking the complete version.
8. Confirm which version is active before generation. Older versions remain part of the history and approved package snapshots.
9. Founder-protected rules require founder authority. Administrative infrastructure access alone does not silently become founder approval authority.

## Expected result
One reviewed active version governs each channel; importing/editing does not silently activate instructions.

## Practice exercise
Import the LinkedIn preset in preview, edit a draft and submit it. Confirm the previous active version remains until explicit activation.

## Common problems and boundaries
No activation button: check role/grants. Existing checks become stale after active workflow/protected-rule changes and must be reconsidered. Do not copy the private brand library into public demo exports.
